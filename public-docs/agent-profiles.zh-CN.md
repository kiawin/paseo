# Agent 配置 {#agent-profiles}

把你常一起使用的设置保存为一个命名配置。创建 Agent 时选择 **UI 工作**、**规划**或**审查**，而不必每次都单独选择模型、思考级别和模式。

- **对你来说**：一次选择即可应用保存的 Provider、模型、模式、思考级别和可用的功能设置。
- **对你启动的 Agent 来说**：配置指令会添加到它的系统提示词中。
- **对负责编排的 Agent 来说**：配置说明解释了在委派工作时何时选择这些设置。

## 创建配置 {#create-a-profile}

1. 打开 **设置 → 你的主机 → Agents → Agent 配置**。
2. 选择 **新建配置**，并为它命名，例如 **UI 工作**。
3. 选择它的 Provider、模型、模式、思考级别以及任何可用的功能。
4. 在 **适用场景** 中填写这个配置应该处理的工作类型。
5. 可选：在 **指令** 中填写从这个配置启动的每个 Agent 都应遵循的内容。
6. 选择 **保存**。

配置保存在该主机上。可用的设置取决于你选择的 Provider 和模型。

## 一键应用设置 {#apply-settings-in-one-click}

创建 Agent 时，打开模型选择器，在 **配置文件** 下选择一个已保存的配置。Paseo 会一并应用其中的设置；发送提示词之前你仍然可以调整。

修改已保存的配置只影响之后的选择，不会更新你已经启动的 Agent。

## 用指令启动 Agent {#start-agents-with-instructions}

**指令** 是写给你启动的 Agent 看的，而 **适用场景** 是写给选择配置的 Agent 看的。为新 Agent 选择一个带指令的配置时，Composer 会显示一个 **{profile} 指令** 标签，发送第一条消息时，这些指令会进入新 Agent 的系统提示词。选择该标签即可去掉它们。

之后修改草稿的模型或模式时，指令会保留。选择另一个配置会替换这些指令；如果那个配置没有指令，就会移除它们。

系统提示词只在 Agent 启动时设置。为正在运行的 Agent 选择配置，只会应用它的设置，不会改变该 Agent 的指令。从配置启动的拉取请求审查者也会收到它的指令。

如果某段文字应该发给主机上的每个 Agent，请使用 **设置 → 你的主机 → 编排** 下的 **System prompt**。

## 用说明指导委派 {#guide-delegation-with-notes}

**适用场景** 字段就是配置的说明。Paseo 通过它的工具公开这些说明，负责编排的 Agent 在决定如何启动执行者之前可以先读取它们。

为每个配置设定清晰的专长：

| 配置    | 示例说明                                                |
| ------- | ------------------------------------------------------- |
| UI 工作 | 用于组件、布局、样式和视觉打磨。                        |
| 规划    | 用于架构设计、排查根本原因以及比较不同的实现方案。      |
| 审查    | 用于独立审查 diff、正确性、缺失的测试和不必要的复杂度。 |

每个配置可以使用不同的 Provider 和模型，也可以对同一个模型使用不同的设置。

[启用 Paseo 工具](/docs/orchestration#get-started)之后，你可以这样要求：

> 查看我的 Paseo 配置及其说明。为设置页面的 UI 改动选择一个配置，然后用审查配置对 diff 做一次独立审查。

编排者会读取配置，为每个任务选择设置，并启动执行者。说明用来指导这个选择；执行者的具体任务要写在它的任务提示词中。

内置的 [Paseo 技能](/docs/skills#paseo-paseo-reference)会指示 Agent 在委派前查看配置并阅读其说明。如果没有合适的配置，它会引导 Agent 发现已配置的 Provider 和模型，并告诉你采用了哪个备选方案。

委派示例见[常用工作流](/docs/orchestration-workflows)，工具接口见 [MCP 参考](/docs/mcp#agent-profiles)。
